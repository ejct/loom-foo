# loom-foo Support

**Project:** `loom-foo` — 40 portable Agent Skills  
**Maintainer:** `ejct` on GitHub

## Get help or report a problem

For non-sensitive support questions, installation problems, documentation errors, feature suggestions and bug reports, use the repository's [GitHub Issues](https://github.com/ejct/loom-foo/issues) when accessible to you.

Before filing, check whether a relevant issue already exists. A useful report includes the Skill name, package version (for example `0.40.0`), host/runtime, what you expected, what happened, and minimal reproducible steps or a sanitized example.

If you are reporting a bug, clearly separate observed behavior from assumptions. Do not describe a simulated result as a completed external action.

## Privacy and security

**Do not publish passwords, tokens, private files, customer data, conversation exports, internal URLs or exploit details in an issue.**

- For a **security vulnerability**, consult the [Security Policy](SECURITY.md) and use GitHub's private vulnerability-reporting feature if enabled. If it is unavailable, open only a minimal non-sensitive issue asking how to establish private contact; do not post the vulnerability itself.
- For a **privacy request**, open only a minimal issue asking for a private contact route. Do not include identifying or sensitive information in public.
- For content held by **ChatGPT, GitHub or a third-party connector**, use that provider's support and privacy controls; the loom-foo maintainer cannot access or delete their internal account data.

## Scope of support

The project can investigate issues in its distributed Skills, manifests, examples and scripts. Host-specific AI behavior, subscription settings, model limits, connector permissions and service outages may need to be handled by the respective provider.

There is no guaranteed response time, service-level agreement or paid priority-support channel.
