# loom-foo Privacy Policy

**Last updated:** 21 November 2026  
**Applies to:** the generic, distributable `loom-foo` Agent Skills package (initial release baseline v0.42.0)  
**Project maintainer:** `ejct` (GitHub account; https://github.com/ejct)

## 1. Scope

loom-foo is a collection of instructions, supporting files and optional scripts for AI-agent workflows. It runs inside a host application or agent environment selected by the user. It is **not** a standalone chat service or a publisher-operated AI backend.

This policy describes the data practices of the **generic distributed loom-foo package and project support channels**. It does not replace the privacy policies of ChatGPT/OpenAI, GitHub, the user's chosen agent host, model provider, connected applications, or other tools. The maintainer's private development installation and its owner-specific knowledge sources are **not included** in the generic distribution.

## 2. What the distributed package does and does not collect

As provided in v0.42.0, the generic package does not include a publisher-operated account system, advertising system, analytics tracker, remote telemetry endpoint, or backend that automatically receives users' conversations.

Merely installing or invoking a loom-foo Skill does **not** send the user's prompts, files, or workspace content to the project maintainer through an infrastructure service operated by this package.

This does **not** mean that using loom-foo involves no personal-data processing. The AI host and any tools or connections the user enables may process prompts, files, tool inputs, results, and related technical information according to their own policies.

## 3. Information you may choose to share with the project

When you voluntarily open a GitHub issue, participate in a public discussion, or submit a contribution, the maintainer may see your GitHub username, the content you post, attachments, and related project correspondence. These may contain personal data if you include it.

Please **do not post passwords, API keys, private repository links, personal documents, customer records, or other sensitive information** in public issues or pull requests. Use the process described in [Support](SUPPORT.md) to request a private contact route before sharing anything confidential.

GitHub operates the underlying repository, issue and collaboration services and may collect other account, device and usage information under its [privacy statement](https://docs.github.com/en/site-policy/privacy-policies/github-general-privacy-statement).

## 4. Host applications and connected services

Some Skills help a user research websites, inspect repositories, read authorized project sources, or prepare changes. Such work may use tools already provided by the host or connected by the user.

- Access to a third-party service is governed by that service's permissions, connection settings and privacy terms.
- A Skill's instructions do not independently authorize access to private materials or publication of them.
- If content is sent to a model, browser, search service, connector or other third party, the host/provider may process or retain that content under its applicable policies.
- **The project maintainer does not control data retention, training choices, account deletion or technical logs inside those third-party services.**

For example, use of ChatGPT is governed by [OpenAI's privacy policy](https://openai.com/policies/privacy-policy/) and applicable product settings.

## 5. Why support information is used

If you voluntarily submit a bug report, issue, contribution or other project correspondence, the maintainer may use what you share to understand the request, troubleshoot, answer questions, review contributions, maintain security and comply with legal obligations.

Where a legal basis is required, this processing may be based on the user's requested interaction, legitimate interests in maintaining a secure and usable project, or a relevant legal obligation, depending on the context and applicable law. This description does not assert that the maintainer controls data processed independently by a third-party host.

No sale of user conversation content or publisher-operated advertising profiling is part of the distributed v0.42.0 package.

## 6. Sharing, retention and deletion

The project does not operate a separate conversation database for generic Skill users.

Public GitHub issues, comments and contributions may remain visible for as long as they are maintained in the repository. The maintainer may close, edit or remove project content within available permissions, but copies, forks, caches, provider records and third-party archives may persist outside the maintainer's control.

For information held by ChatGPT, GitHub or a connected service, consult that provider's privacy controls or contact the provider directly. The project maintainer cannot directly delete another service's account records or conversation history.

## 7. Security and your choices

Use the host's permissions and connector controls to decide which files and external services an agent may access. Review consequential outputs and approve external actions before execution. Do not put sensitive information into public GitHub support channels.

For security reporting, see [Security Policy](SECURITY.md).

## 8. Privacy requests and contact

For questions about this project's handling of information voluntarily posted to its GitHub channels, see [Support](SUPPORT.md). You may request access, correction, removal or other applicable rights regarding information within the maintainer's control. **Do not include private personal details in a public issue.** Instead, create a minimal non-sensitive request for a private contact method.

Requests concerning data held by OpenAI, GitHub, your AI host or another connected service should be sent directly to that provider. Any legal rights you have under applicable data-protection law remain unaffected.

## 9. Changes

This policy may be updated when the distributed package, support channels or processing practices change. The date at the top identifies the published version. Material changes should be reflected in the repository's change history.

**Publication note:** This document is prepared in a currently private repository. A GitHub URL becomes a public policy URL only when readers without repository access can open it.
