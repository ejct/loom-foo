# ISR sealed execution protocol v0.1.1

Use only when independent reconstruction is a real task or the audit needs stronger evidence provenance. It is optional for same-context analysis.

## Role and information boundaries

| Role | May access | Must not access before freeze | Main artifact |
|---|---|---|---|
| Coordinator / brief preparer | Product requirements; incumbent for compatibility classification | Must not include incumbent mechanics in reconstructor packet | Neutral brief, leakage audit, decision question |
| Reconstructor R1 / R2 | Identical sealed neutral brief; necessary non-incumbent product sources | Incumbent architecture/code; peers' outputs; prior scores/verdicts | Exact first design, assumptions and failure paths |
| Reviewer / comparator | Sealed brief, frozen candidates, scenarios; later incumbent | For blind review: candidate origin and method labels | Scenario outcomes, conflicts and comparison |

Real isolation is context and available-material separation, not a claim about distinct neural-network training. A fresh context with broad tools capable of reading incumbent material is weaker than one with restricted tools; record access capability and actual calls, then use `UNVERIFIED` when it cannot be shown that incumbent was withheld.

## Sealed input manifest

Record: decision ID, date/version when available, product owner and intended user outcome, source locators and hashes, authoritative requirements vs compatibility constraints, exact brief bytes/hash, exclusions, scenario precommit, cost/permissions. Neutrality review: remove solution-specific entities, code paths, inherited optimizations, prototype artifacts, and previous rejected designs. If a constraint implies the incumbent mechanism, justify it as unavoidable or exclude it from a greenfield comparison.

## Candidate receipt

Record whether the coordinator actually loaded this ISR Skill, its observed version/source identity, or merely applied the method from a Task Brief. This is separate from candidate isolation and never inferred from the result.


For each independently invoked reconstructor record: context/session/run identity or `UNKNOWN`, model when known, exact prompt and source set, tool access boundary, actual output, first-result hash, completion/failure status, attempts, uncorrected counterexamples, subsequent revisions with parent linkage, elapsed/cost if verified. A recorded retry does not replace the first response. If only partial material is available, classify it rather than inventing an evidence receipt.

## Evaluation and unblinding

1. Freeze prompts, candidate outputs, comparison cases and rubric. An existing accepted rubric takes precedence over newly proposed metrics.
2. Check product hard requirements and dependency contexts before preferring simplicity. Check at least one counterexample that might refute each material performance/safety claim.
3. Review global, local and mixed states as appropriate to the task; do not pretend a structural check verifies semantic quality.
4. Preserve reviewer first verdict before disclosing method labels when blind evaluation is actually available.
5. Reveal incumbent after candidate freeze; crosswalk mechanisms and product vs inherited constraints. Preserve original judgments and attach any post-unblind amendments.
6. Keep user acceptance, migration authorization, code execution, and changes to canonical project docs outside this evaluation.

**Post-unblinding viability and incremental value:** First identify authoritative product requirements and explicit owner mandates, including technology or generation-method mandates, separately from inherited implementation choices. A conflicting candidate remains preserved as a greenfield/diagnostic counterfactual, not an approved or compatible substitute. Classify material comparisons as new, already documented, confirming/convergent, or not evidenced. Preserve the original candidate and any conflicting evidence; do not retroactively change its sealed brief.

## Minimal comparison record

| Scenario | Hard criterion | R1: observed/inferred | R2: observed/inferred | Incumbent: observed/inferred | Discriminator / risk | Missing evidence |
|---|---|---|---|---|---|---|

Finish with actual mode and isolation evidence, candidate frozen IDs, `RETAIN | LOCAL_ADAPTATION | TARGETED_PROBE | ARCHITECTURE_CHANGE_PROPOSAL | NO_NEW_ACTION`, a single smallest action, or a precise blocker.

## Stop / recovery rules

- Isolation unavailable, essential to user request: `BLOCKED_INDEPENDENCE`; preserve the preparatory brief; do not fabricate separate outputs.
- Isolation unavailable, analysis still useful: `SAME_CONTEXT_CHALLENGE`, a *different evidence class*; never use it to prove ISR gains over an ordinary review.
- Neutral brief contaminated: repair *before* reconstructor invocation, record revised version and why; after candidate outputs are visible, preserve earlier results and treat redesign as another run.
- Alternative violates immutable requirement: retain the failure and exclude from viable set; do not quietly change the requirement.
- No independent difference: record `NO_MEANINGFUL_DIVERSITY`; don't invent diversity or force a new experiment.
- No decision-relevant uncertainty remains: `NO_NEW_ACTION`; no ceremonial report series.
