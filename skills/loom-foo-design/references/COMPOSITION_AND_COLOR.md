# Composition, layout and color — cross-disciplinary design foundations

Load when the work requires structural visual decisions across text, imagery, controls or multiple media. This reference belongs to the general `loom-foo-design` skill; do not activate a second specialist merely because a work includes a grid or color.

## Composition is a response to meaning

- Define the desired first perception, second reading, and intended action/understanding. Rank actual content before selecting visual treatment.
- Map hierarchy to differences that survive realistic usage: scale, space, alignment, contrast, position, rhythm, density, imagery and typographic roles. Do not equate visual loudness with importance.
- Select an organizing mechanism: grid, axis, sequence, spatial grouping, asymmetric balance, editorial rhythm, intentional disruption, modular system or another grounded composition. A grid is an instrument, not the aesthetic goal.
- Separate grouping from mere proximity when labels, captions, controls and legends must maintain semantic relationships. Check scan path and ambiguous associations.
- Make optical corrections at the intended size: apparent centering, curved/diagonal forms, dense glyphs, perceived rather than mathematical balance.
- Design with real text, longest labels, translated strings, actual data and supplied assets. Placeholder text can disguise broken line length, layout density or intent.

## Color decisions

- Start from the semantic and perceptual job: identify, distinguish, emphasize, group, signal state or establish atmosphere. Don't use hue as the sole signal for a crucial distinction.
- Evaluate relationships across background, text, interaction states and compositional areas. Compare in context; a standalone swatch is insufficient.
- Check contrast with tools for applicable web UI text where possible; never claim WCAG compliance solely from guessed RGB values or a palette image. Consider gradients, overlays, transparency, antialiasing and actual rendering.
- Check grayscale, reversed/light-dark settings and actual output device/substrate when important; don't force strict minimal palettes or fixed 60/30/10 recipes.
- Preserve existing brand tokens and agreed language unless authorized to redesign them.

## Review the real output

1. At the actual target scale or viewport: what does the viewer notice first, and is that correct?
2. Inspect for collisions, unintended alignment, weak grouping, or a strong element hijacking hierarchy.
3. Verify text/number fidelity, relevant responsive layouts, compression/cropping and actual editable source where requested.
4. Fix the specific failure; compare before/after only when comparison adds evidence.
5. If a deeper critique of an existing design is the **requested output**, prefer standalone `loom-foo-design-review` when present; this self-check remains built in for creation.
