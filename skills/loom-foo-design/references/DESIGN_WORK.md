# Design work: proportionate methods

Use to create, revise or critique real designs. Select applicable tactics rather than running every step.

## Establish an intent that can guide decisions

- **Task:** what will the audience recognize, understand, decide, feel or accomplish?
- **Audience / context:** device, environment, viewing distance, time budget, accessibility, language, cultural context.
- **Constraints:** content and evidence, brand, production method, permitted tools, expected artifact, privacy, cost.
- **Proposition:** articulate one core functional or communication idea. For static work, ask what the viewer should understand in the first few seconds. For UX, ask which decision/action must become easier and how success could be observed.
- **Uncertainties:** distinguish given facts, assumptions and design hypotheses. Avoid broad external research unless it can change the result.

## Art direction and graphic design

1. Derive a visual concept grounded in the purpose. Choose references for *mechanisms* (composition, rhythm, emotional register, metaphor, material, visual hierarchy), not for cloning an existing work.
2. Make deliberate choices about visual hierarchy, contrast, proportion, color, type, negative space, imagery and semantic alignment. These are trade-offs, not universal recipes; avoid imposing rounded cards, gradients, minimal text, fixed numbers of options or a single signature style.
3. Compose around real content and actual output dimensions. Test at realistic scale, cropping, contrast and reading conditions.
4. If multiple variants would clarify a genuine decision, vary concepts/mechanisms rather than only palettes or superficial ornaments. Otherwise create one strong direction.
5. Critique against the intent: What is perceived first? What is misunderstood? What feels generic or inconsistent? What specific change would improve it? Fix the highest-impact issue, inspect again.

## UX, product, interaction

1. Ground behavior in user goals and source-supported constraints. Model objects, meaningful actions, transitions, failure states and dependencies.
2. Preserve user control, understandable feedback, error prevention/recovery, accessibility and nonvisual cases as needed. Avoid over-specifying flows when the user asked for a bounded UI edit.
3. Ensure visual decisions support interaction affordances; a static screen cannot prove the interaction. Prototype only the fidelity needed for the user's decision.
4. Evaluate realistic tasks/states, not just ideal-path screens: empty, loading, permission, invalid, interrupted and recovery states where material.
5. Distinguish design rationale from research evidence; do not claim usability, conversion or user preference without tests.

## Branding, editorial and information design

- **Identity:** the mark identifies; the system must work across sizes/surfaces/languages. Separate conceptual distinctiveness from unverified legal ownership or trademark clearance.
- **Editorial:** the document has narrative rhythm across pages. Test headline/body/captions/tables, long text, localization and content completeness; grids are tools, not inviolable rules.
- **Information:** establish one or a few truthful takeaways from reliable sources; select layout according to relational structure (sequence, comparison, hierarchy, overlap, flow, measured trend). Render numerical labels/text from controlled inputs; use graphics only where they clarify.
- **Typography:** check target scripts, including Ukrainian characters such as і, ї, є, ґ, apostrophe, numerals and punctuation when relevant; look at actual font specimens and licence boundaries.

## Review and redesign

- If asked for critique only, deliver a prioritized, evidence-limited assessment; do not mutate files.
- If asked to improve, preserve accepted content/identity and change only needed elements; favor a visual before/after or specific changed artifact.
- Separate objective defects (missing text, clipped content, broken contrast, invalid file) from subjective art-direction trade-offs. Do not create fake numerical ratings.
- If using specialist or generative tools, inspect actual outputs rather than relying on their self-descriptions. Reject inaccessible or unaudited external code as a mandatory requirement.
