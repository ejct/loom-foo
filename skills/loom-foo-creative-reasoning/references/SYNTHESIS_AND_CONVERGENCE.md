# Selective synthesis and purposeful convergence

**Load when:** several distinct valid ideas need reconciliation, or choosing between them hinges on novelty vs actual usefulness, compatibility or consequential trade-offs.

## Synthesis

- Extract the *independent functional benefit* from each surviving direction.
- Combine only if input/output assumptions, geometry/behavior, user goals and technical constraints are compatible.
- If one benefit requires weakening an accepted invariant, do not silently combine it. Prefer a staged or context-dependent choice only when behavior remains comprehensible.
- A hybrid must have a coherent new causal mechanism, not be an indiscriminate collage of attractive elements.

## Convergence

1. Reject any concept violating hard constraints, authority boundaries or technical feasibility.
2. Compare **novelty** and **usefulness** separately. A surprising concept is not necessarily more usable, maintainable, readable or effective.
3. Account for evidence strength: established source fact, expert reasoning, untested hypothesis, measurable behavior. Do not score imagined evidence as observed.
4. Prefer the least risky direction that addresses the actual failure and can be checked with available tools; a conservative option may win.
5. If the user requested a portfolio of alternatives, preserve meaningful differences and do not force a winner. Otherwise return one recommended direction with the principal trade-off.
6. Make the smallest discriminating check when uncertainty matters. Stop before an arbitrary brainstorming quota, multi-agent consensus ceremony or prolonged alternatives list.

## Stopping rule and accepted state

An accepted concept transitions into **production**: implementation, local refinement, test, export, verification. Do not reopen conceptual exploration merely because an output is imperfect. Reopen on changed objectives, evidence that the working principle fails, or explicit user instruction.

## Handoff shape (optional)

- Chosen concept and why it wins.
- `FIXED` invariants, remaining flexible variables and prohibited changes.
- Expected artifact and actual acceptance checks.
- Critical unknown or caveat only if decision-changing.

A short in-line handoff suffices; never impose a document or pause the task when execution is feasible and already requested.
