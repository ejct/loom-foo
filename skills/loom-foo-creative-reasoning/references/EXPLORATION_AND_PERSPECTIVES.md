# Reframing and divergent exploration

**Load when:** the question itself may be too narrow, or a real decision needs causally distinct alternatives. The L1 contract remains binding: do not rewrite the user's accepted goal, source data or constraints.

## Problem frame before solutions

- Distinguish an **outcome** (“readers can orient and recover original text”) from an assumed **solution** (“every passage must be shown as an accordion”). A proposal may challenge only the assumed solution, not the accepted outcome.
- Name one productive alternative frame only if it unlocks a new class of valid solutions; otherwise skip reframing.
- When constraints are dense, identify which are *hard invariants* and which are assumptions about current implementation. Do not treat unverified assumptions as user permission.

## Mechanism diversity, not surface variation

Choose one or two suitable devices, not a compulsory checklist:

- **Inversion:** reverse a habitual implementation assumption; test compatibility with invariants.
- **Functional decomposition:** split conflicting jobs and reassign functions to different elements, stages or contexts.
- **Cross-domain analogy:** find a shared *causal relation*, map inputs/actions/outcomes, list where the analogy breaks. Don't copy superficial styling or assert empirical fit.
- **Knowledge-space shift:** consider a genuinely different knowledge tradition, profession, user setting, material practice or use situation. Derive its relevant constraints/heuristics rather than inventing quotations or pretending to embody a real person. Perspectives can be speculative; label them.
- **Morphological search:** vary independent structural dimensions and combine only semantically/physically compatible choices.
- **Contradiction resolution:** distinguish constraints that conflict at one scale but can be separated by state, modality, timing or optical size.

## Distinctness check

Two ideas are materially different when they change the **causal way the outcome is achieved**, not merely the adjective, color, surface, metaphor name or copy. If all candidates share the same failure mechanism, make a different decomposition or stop and diagnose with `references/FIXATION_AND_FAILURE_DIAGNOSIS.md`.

For each relevant alternative: mechanism, which invariant survives, why it could help, principal failure, and the lightest decisive check. One strong option can be sufficient. Do not force a fixed number.

## Perspective caution

Invented personas do not supply real user evidence. Varied perspectives may widen a search but are not independent human participants, separate agents or verified diversity. For high-stakes product effects, use real user evidence where available before claiming a better result.

## Exit

When a direction is viable, return it to the output owner. If the user requested a finished image, UX flow, code patch or text, do that work instead of stopping at ideation, within authorized capability.
