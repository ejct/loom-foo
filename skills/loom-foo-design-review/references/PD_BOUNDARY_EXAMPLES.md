# design-review — conditional method

> Preserved sections from private Loom-foo 0.35.1 SKILL.md. Referenced `references/...` paths are relative to the owning skill root. L1 activation and authority remain controlling.

## Example boundaries

- “Оціни цю іконку на 16, 32 і 64 px, без редагування” -> Design Review: inspect actual sizes and report optical/geometry findings; icon specialist only when editing is requested.
- “Compare two landing-page designs for clear sign-up intent” -> Design Review: criterion-anchored comparison, uncertainty about actual conversion.
- “Make this slide deck typographically better” -> Typography or producing owner, with its own QA; Design Review is not obligatory.
- “Check whether this rendered screen matches a supplied design system” -> Design Review's scoped visual/interaction AUDIT; no assumption of system governance rights.
- “Audit semantic token drift across Figma and CSS; plan a migration” -> Design Systems, not artifact critique.
- “Check glyph support and 200% text reflow only, without editing” -> Typography, not cross-disciplinary critique.
- “Review code changes to this button component” -> Engineering Change Review.
- “Цей макет виглядає чудово, чи є проблеми?” -> investigate fairly; potentially conclude no material defect, rather than contrive criticism.
