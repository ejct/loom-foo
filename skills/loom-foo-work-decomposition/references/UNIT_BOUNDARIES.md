# Unit Boundaries

Split work only for real semantic/execution boundaries.

Strong split signals:
- independently acceptable outcomes;
- different prerequisite gates;
- genuine parallelism;
- different authority envelopes;
- different natural owners/executors;
- different verification boundaries;
- multiple independent stop conditions;
- sequencing needed to avoid invalid downstream work.

Keep work together when mechanics, subject, verification, and acceptance are inseparable.

The best decomposition is the minimum sufficient unit set, not the largest task count.

A Work Unit should remain one level above Task Brief detail.
