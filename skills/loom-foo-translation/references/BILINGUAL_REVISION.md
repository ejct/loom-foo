# Source readiness, bilingual revision and post-editing

Use when translation-specific source readiness is requested/material, or the user asks to repair/revise an existing target. No mandatory preflight for ordinary translation.

## Readiness

Bind purpose, audience, locale, source revision and constraints. Inspect the actual problematic span. Distinguish intended ambiguity (e.g. pun, irony), missing referent/context, contradiction, source error, protected wording and format-dependent constraints. Explain the consequence for translation and possible faithful renderings; ask only when material choice blocks the result. Separate proposed source correction from the source and record authoritative answer if obtained; never silently alter original facts. For a readiness-only request return findings/questions, not an unsolicited translation. For a partially resolvable task continue supported sections and mark remaining gaps.

## Existing target work

1. Establish exact source and existing target, their relationship, approved/untouched spans and authorized edit scope. If the target's origin (human/MT/AI) is unknown, don't invent it. If exact original is missing, offer bounded target-only editing or conditional concerns, not a bilingual fidelity certification.
2. Select the smallest useful operation. Bilingual diagnosis alone is Translation Analysis; target-only spelling/style is Editorial Review. A repair request authorizes only the requested changes. For post-editing distinguish light adequacy/critical-error repair from broader publishable naturalness according to the brief, not an assumed industry score. If localized repair cannot restore meaning, propose or use scoped retranslation when authorized. Do not claim an independently generated alternative if the current target was visible.
3. Compare source and target at the affected meaning unit and surrounding dependencies. Correct supported defects, not neutral preferences. Retain unaffected accepted wording (exact bytes when the contract requires it); check references, protected tokens, numbers, polarity, modality, register, terminology and dependent spans. Use a diff or explicit local changes when helpful; do not regenerate unrelated text.
4. Return the repaired target/patch in the requested format. Keep unresolved items, optional improvements and actual checks separate from applied edits. For regulated or consequential material identify required qualified review without claiming approval, certification or independent review. Use existing format checks and compare meaning separately.

Example (synthetic): source `The amount may be refunded. Contact support.`; existing `Суму буде повернено. Зверніться до служби підтримки.`; repair only modality -> `Суму може бути повернено. Зверніться до служби підтримки.` Do not rewrite the second sentence or silently edit the source. A critique-only prompt gets findings instead of an applied change.
