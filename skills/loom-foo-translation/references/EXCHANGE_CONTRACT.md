# Translation exchange contract v0.1

Use only when structured output or a multi-stage caller requires it. Ordinary text is the default. This is a portable data shape, not a runtime or a new skill. Both skills carry the same reference; keep them byte-identical when revising. See `assets/exchange.schema.json` in the skill directory for structural constraints. Return JSON alone when requested; no Markdown or receipt. Never claim validation unless actually run.

- `schema_version`: `0.1`; `operation`: `translate` or `analyze`; `status`: `complete`, `partial`, `unsupported`.
- `versions`: ordered objects with `id`, `text` (exact immutable Unicode, null if unavailable), `language` (name/tag, optionally `und`), `profile` (optional period, region, dialect, medium, speaker, audience, genre, context), `evidence_status` (optional `attested`, `reconstructed`, `simulated`, `unsupported`), `source_locator` (optional). Do not normalize after recording anchors.
- `steps`: ordered edges with `id`, `source_id`, `target_id`, `kind` (`translation`, `oral_retelling`, `composition`, `revision`, `reconstruction`, `simulation`, `unknown`), `lineage` (`documented`, `hypothetical`, `mixed`, `unknown`), `isolation` (`isolated`, `shared_context`, `unknown`, `not_applicable`), optional `strategy` and `context_available`. Use unknown if not observed.
- `findings`: property-level objects with `id`, `step_id` (null for direct endpoint comparison), `source_id`, `target_id`, `source_spans`, `target_spans` (arrays of exact quoted anchors; empty means no corresponding span, not a zero-length fabricated quote), `property`, `dimension`, `source_state`, `target_state`, `type` (null if undetermined), `assessment`, `certainty` (`supported`, `conditional`, `unresolved`), `explanation`, `consequence`, optional `alternatives`, `evidence` (actual checked locators), `translatability` and `decision_note`. Distinguish directly observed facts from inference in explanation. A finding can link multiple spans on either side; not every token needs a finding. A null `type` requires unresolved certainty.
- `notes`: material limitations, missing context and coverage gaps. A `complete` status is completion of the requested scope, not proof of absolute quality. If analysis finds no material change, an empty findings array plus coverage note is valid. Translation may return an empty findings array; do not fabricate analysis. If a version's text is null, do not supply anchors into it.

## Span semantics

Each anchor has `quote` plus optional paired `start`/`end` (zero-based Unicode code point offsets, half-open, in the exact version text); `occurrence` may identify a repeated quote (1-based, left to right, non-overlapping). Provide offsets only if calculated or verified. Exact quote must equal `text[start:end]`; when repeated and no offsets, include occurrence or enough context. A finding with empty source or target spans must explain the omission/addition or distributed/contextual evidence. A missing intermediate is not an empty translation.

## Caller integrity checks

JSON Schema checks shape, not semantics. Check unique version, step and finding IDs; references resolve; step direction agrees with finding; endpoint findings refer to actual versions; offsets match the exact quote; occurrence is valid; graph respects caller's route; no unsupported claim is disguised as observed. Verify text against user input. For `translate`, target must be present unless partial/unsupported; for `analyze`, missing originals cannot yield supported comparative findings. If no validator is available, say validation is unconfirmed. Do not modify source records merely to satisfy the schema.
