# Choosing and using language resources

Use when terminology resource selection, a supplied glossary conflict, repeated terminology decisions or context-sensitive reuse materially affects translation. Ordinary translation needs no resource setup.

- A dictionary/lexical source helps with senses and usage; a project glossary with preferred terms helps consistent domain expression; a concept-oriented termbase helps when senses, definitions and cross-language mappings must remain distinct. A style guide governs voice/conventions; parallel texts and translation memories supply candidate usages, not truth. Select the smallest sufficient resource, native format and current scope.
- Check actual approved version, concept and usage context before applying a term. Same string may denote different concepts; a familiar technical term may appropriately stay untranslated. Do not enforce every occurrence identically or convert a provisional term into an approved decision. Distinguish preference from required terminology.
- Use up-front, concurrent, delegated or minimal terminology work depending on actual constraints. Accumulate unresolved candidates during translation and revisit affected units. Honor an explicit project prerequisite, but do not block every ordinary term on new approval. For a term decision or reusable glossary construction consult Terminology when material; for simple lookup use supplied resources/Knowledge Retrieval. If unavailable, keep a bounded working list and flag unresolved terms.
- Inspect larger context before reusing memory segments; check coherence, changed scope, referents and meaning. Do not send private source to unapproved external services or install a tool solely to satisfy this reference. No requirement to create or persist a glossary. Resource mutations require existing authorized project scope.
