# Multilingual maintenance

Use for synchronizing previously maintained translations when a source/peer version or resource changes. Respect the project's native conventions and authorized target files; this is a language maintenance method, not canon approval or deployment.

1. Identify language versions, stable unit IDs where available, last confirmed pair, current revisions, relationships and controlling authority. Known derived source, coequal versions and unknown lineage are different. Missing prior pair means change scope is unknown; avoid asserting that unrelated content is unchanged. Ask only for blocking inputs or produce a clearly bounded candidate.
2. Inspect actual diff/changed content at meaningful unit boundaries. Distinguish meaning changes, editorial changes, code/format changes, term decisions, new/deleted units and dependencies (referents, terminology, numbering, links, UI state). A project's ID-change policy may distinguish semantic from cosmetic changes; never change keys or source conventions on your own. Use native version-control/catalog tools if available.
3. Update affected target units with necessary contextual adjustments, preserve unaffected text and protected material. Apply an identical mechanical code edit only where appropriate and authorized; it is not a linguistic judgment. If both versions changed or authority conflicts, isolate divergences and obtain/return the needed decision; do not choose a canonical version by recency, majority or fluency. Use Translation Analysis for actual peer comparison if needed.
4. Verify the precise changed artifact against the intended diff and source/target meaning. Check unchanged ranges as required, dependent units, format profile and actual build/render only where observed. Hashes/diff indicate bytes or freshness, not equivalence. Track source revision, target revision, reviewed vs proposed state and remaining gaps in the project's native format when requested. Do not invent a persistent ledger or require a universal metadata schema.

Synthetic example: a source's cancellation window changes from 14 to 30 days, while an unrelated paragraph is already approved. Update the window and dependent references; leave unrelated target unchanged. A punctuation-only source edit may need no target change. Where one language version is legally coequal, surface the discrepancy rather than silently treating the other as source.
