# Solution-space exploration and agent knowledge delivery (portable projection)

For consequential new-skill/portfolio choices, use a *conditional*, non-linear five-move sequence:

1. **Semantic grounding:** user outcome, distinctions, constraints, authority and target runtime. Verify external facts/standards early when needed.
2. **Initial mechanism draft:** status quo, existing owner, standing instructions, retrieval, script/tool, candidate new skill; keep only materially distinct choices. This is a pre-search snapshot, not proof of cognitive independence from all examples.
3. **Bounded prior art:** consult current official spec/creator guidance, other implementations, outcome/failure evidence where it could change the decision. Search by outcome rather than only the favored format.
4. **Reconciliation:** compare alternatives on equal constraints; retain, adapt, combine, discard or reopen framing. Do not privilege first ideas or outside examples. Log `NO_LOCAL_DELTA` when warranted.
5. **Convergence:** select smallest supported surface and owner, develop exact artifact, check activation/freshness/permissions and only proportional behavioral evidence.

Small local repairs skip discovery when it cannot change the choice; explicit external landscape questions may search directly. Do not delay correctness/safety API checks to preserve independent ideation.

## Knowledge delivery surface

- One task -> prompt/Task Brief.
- Always needed repo rule or canonical index -> `AGENTS.md` / scoped runtime instructions.
- Large or changing facts -> source retrieval with version and authority.
- Reusable selectively activated procedural reasoning -> existing or new Agent Skill.
- Deterministic calculation/check -> script/test/template.
- Authenticated service/action -> authorized API, MCP or connector.
- No material improvement -> no new artifact.

Compare expected frequency, activation chance, context cost, freshness/drift, portability, authority, security and update budget. Surfaces may compose. `loom-foo-skill-engineering` owns skill lifecycle/surface choice; `loom-foo-architecture-design` owns broader system architecture; `loom-foo-agent-task-design` owns bounded task runtime projection. No central router or new mandatory skill identity.
