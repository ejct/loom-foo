# Reusable skill engineering lessons

This portable reference captures generalized methods from a bounded, privately documented history of skill creation and revision. It **does not** include personal/project source links, connected account identifiers, exact operational project state, or claim exhaustive historical coverage. To audit provenance, obtain appropriate project-local evidence separately; do not treat this file as original source evidence.

## 1. Necessity and owner boundaries

A skill earns an independent identity through a distinct recurring operation, primary output, completion condition, ownership boundary, composition value and proportional cost. An existing owner, a policy, a template, a runtime capability or no new skill may be the right result. Do not multiply skills because a topic is important.

## 2. Source, delivery and activation are different

A source file, ZIP package, repository tree, installed runtime copy, skill discovery and automatic routing are distinct evidence layers. A Git or Drive update cannot establish that ChatGPT or Codex loaded the changed skill. Runtime and source versions may diverge legitimately. Observe the exact loaded instance before attributing behavior.

## 3. Domain specificity and separate tool adapters

In a multi-skill specialized domain, separate semantic owners from research records, state stores, adapters and runtime orchestration. Passing static checks may confirm safer evidence handling while field results remain unproven. Outcome measures should follow the domain's real user objective, not the number of skills or test cases.

## 4. Frozen validation is specialized work

Skill comparison requires an exact tested subject, predeclared cases/oracles, controls against contamination, routing/composition/error analysis, and comparable runtime conditions. Authoring a fixture or inspecting the candidate in the same context cannot prove comparative lift. The skill under test cannot certify itself as valid or canonical.

## 5. Preserve user utility

Strengthening architecture or adding a large evaluation program must not automatically block a known safe user-visible workflow. Keep restoration, hardening and enhancement separate when technically possible. An evidence gap is not by itself authority to restart research or redefine the user's goal.

## 6. Semantic correctness precedes installation

A correct Markdown package can still be wrong about domain vocabulary or source authority. Exact evidence states and negative-claim scope matter. A strictly parsed YAML package can uncover defects that a regex-based check misses. Check both source semantics and syntax; neither proves runtime behavior.

## 7. Mutable project truth is not skill doctrine

Installed skill bodies can preserve stale aliases, identities or inventory assumptions while the authoritative project state changes. Write durable procedural rules into reusable skills; resolve volatile domain facts from current sources at execution time. Repair installed copies only after verifying the selected source/version and appropriate authorization.

## 8. Describe a skill succinctly

A portfolio of long, overlapping descriptions can lose important routing distinctions and trigger excessive invocation. Frontload the operation and negative boundary; move specialist-mode detail into conditional references. File length is a risk factor, not evidence that the skill fails in a specific runtime.

## 9. Skill self-application is diagnostic

One development cycle can legitimately improve its own validator and identify weaknesses, but a self-produced report is not independent evaluation. Preserve a frozen base, actual change, targeted negative regression, and a clear separation of checks performed from checks merely written.

## Provenance policy

These are engineering heuristics derived from a bounded historical source corpus, not universal outcomes. Detailed private source citations belong to a separately permissioned audit record. For current skill versions and operation details, consult actual installed SKILL.md instructions and target project authority.
