# Skill Engineering — conditional specialist composition

This is a routing guide for engineering **skills**. It is not a universal pipeline, mandatory owner chain or dependency graph. Select the smallest specialist whose **primary output** is materially needed. In tool-limited runtimes, perform honest ordinary work without asserting the specialist was loaded.

| Concrete need | Preferred owner / role | Required boundary |
| --- | --- | --- |
| A repeated workflow merits a new skill? | `loom-foo-skill-engineering` ASSESS + surface selection | May choose standing instructions/reference/tool/no new skill; no creation by default |
| Blocking ambiguity in what the skill should accomplish | `loom-foo-problem-understanding` when framing blocks engineering | Bounded Understanding Model, no mandatory upfront step |
| Recover many prior skill incidents/lessons | `loom-foo-cross-context-transfer` for Generalize/Synthesize | Corpus and provenance; don't generalize from a single anecdote |
| Search external examples or alternatives for consequential new work | `loom-foo-skill-engineering` bounded discovery, optional `loom-foo-cross-context-transfer` for synthesis | First form an internal solution-space draft when the choice is open; then search by desired outcome, reconcile and allow framing changes. Facts/standards can be checked earlier. |
| Diagnose a reported failure | `loom-foo-failure-learning` | Recover active task, trace smallest causal owner; output incident evidence |
| Complex alternative/proposal for skill portfolio | `loom-foo-proposal-refinement` | Proposal quality and adversarial refinement; does not install or canonize |
| Design a changed skill-system architecture/composition | `loom-foo-architecture-design` | Architecture only when dependencies/boundaries materially change |
| Review an existing skill-system architecture | `loom-foo-architecture-review` | Reviewer findings, not redesign; can be self-review if no independent reviewer |
| Formal semantics or contract acceptance conditions | `loom-foo-specification-design` | Define behavioral contract; no automatic authority transition |
| Draft/scaffold standard SKILL.md or ZIP | Platform `skill-creator` when available | Authoring and available trigger/task eval tooling; not portfolio acceptance or self-proclaimed empirical lift |
| Inspect a change for defects or unintended effects | `loom-foo-change-review` | Exact base/candidate and affected surfaces; review ≠ verification |
| Check exact candidate against accepted properties | `loom-foo-change-verification` | Criterion-level actual checks; PASS ≠ accepted |
| Design a discriminating evaluation plan | `loom-foo-research-design` | Use smallest credible probe; don't manufacture tests if not decision-relevant |
| Execute frozen skill C0/C1/C2 campaign | Optional `loom-foo-skill-validation` export | Frozen subject/cases/oracles; check exact runtime availability first; unavailable means no substitute campaign; cannot establish its own validity |
| Reconcile accepted skills-related project docs | `loom-foo-project-knowledge-stewardship` | Only within separately authorized persistence transition |
| Prepare bounded implementation brief for an agent | `loom-foo-agent-task-design` | One already-scoped work intent; not broad project strategy |

Shared method context: read `references/SOLUTION_SPACE_AND_DELIVERY.md` for the conditional semantic exploration → initial alternatives → bounded prior art → reconciliation → convergence pattern, and knowledge-delivery choice. This method remains owned by the appropriate output specialist.

## Case-shaped composition, not mandatory choreography

- **New skill from recurring cases:** ASSESS -> bounded transfer (if histories material) -> proposal/design only if consequential -> author -> static/first-use -> exact receipt. Do not call architecture-review just because a `SKILL.md` exists.
- **Minor instruction repair:** identify base -> edit one clause -> affected smoke/static checks -> receipt. No proposal or architecture campaign.
- **Recurring wrong owner:** route/failure investigation -> inspect installed descriptions and negative examples -> smallest description/routing revision -> actual host routing check where available. A valid ZIP is insufficient.
- **Multi-skill overlap:** portfolio local-delta assessment -> cross-context evidence/architecture review only as needed -> explicit keep/merge/slim/split recommendation. Don't silently delete or migrate other skills.
- **Frozen A/B request:** delegate only when `loom-foo-skill-validation` is present in the exact runtime; otherwise report UNAVAILABLE and do not recast it as routine `FIRST_USE` or run a substitute campaign.
- **Self-engineering (this skill):** source freeze -> inspect actual composition gap -> proposed delta and architecture scenario review -> bounded implementation -> change review + deterministic package checks -> record same-context limitations. Independent confirmation stays separate.

## Authority/provenance guard

A specialist read/review gives evidence or an artifact; it does not grant publish/deploy/install/merge rights. When only its SKILL.md has been consulted, call that **guidance loaded / method applied** rather than an independently executed specialist service. A self-run adversarial review is one execution context; reports must say so.

Do not hard-code any contributor version or repository path as universally current. Resolve each available specialization at use time. General historical lessons are in `EXPERIENCE_AND_EVIDENCE.md`; detailed dated project inventories must be resolved separately from authorized private sources.
