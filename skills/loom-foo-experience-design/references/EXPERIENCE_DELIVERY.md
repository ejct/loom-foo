# UX artifacts and evidence fidelity

| Requested output | Make | Do not misrepresent |
| --- | --- | --- |
| User flow / service blueprint | Actual actors, system/user steps, dependencies, exceptions | A flowchart that drops failure transitions |
| IA / navigation architecture | Taxonomy, location, retrieval strategy, sample task paths | An unsupported claim about measured findability |
| Behavior specification | Triggers, states, feedback, accessibility, interruption/recovery, acceptance examples | Product decision as if already accepted |
| Wireframes/UI | Grounded content, real states and interactive semantics | Static screens as functioning prototype |
| Prototype | Real runnable interaction, inspect flows in runtime | Unopened HTML/source as verified behavior |
| UX review only | Refer to Design Review as primary result owner | Editing when critique only was asked |

## Evidence types

`DESIGN_RATIONALE` is not `USER_RESEARCH`; an observed usability test requires real participants and recorded methods, and analytics requires actual data. A single same-context agent walkthrough can find defects but cannot independently establish utility or conversion lift.

## Collaboration with experienced designers

Assume expertise when demonstrated. State meaningful assumptions and disagreements succinctly; propose mechanisms with trade-offs, not doctrine. Ask for missing source context only when the choice materially depends on it. Preserve prior decisions unless explicitly reopened. Present a high-signal critique that a professional can act on; don't automatically generate personas, user stories or workshop artifacts.
