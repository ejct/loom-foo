# Controlled revisions to an accepted identity

Load when an already approved brand mark, wordmark or signature is being edited. This procedure extends the root fast path, not an extra approval gate.

## 1. Pin the right baseline

Use the latest accepted **actual** file/image and the current instruction. If several alternatives exist, do not substitute an unapproved concept. Record which file, version, page/frame or source layer is accessible; if source was not supplied, a screenshot alone supports visual matching, not identical vector paths or font files. Resolve a genuine conflict in protected constraints before destructive editing.

## 2. Small change envelope

- **PRESERVE:** approved mark geometry outside the requested region, wordmark glyph family/shapes, wording and case, brand colors/type roles, important optical relationships, specified crop/size and any earlier accepted corrections.
- **CHANGE:** only the explicitly requested geometry, spacing, size, position, finish or other named dimension.
- **OPEN:** incidental choices that the brief expressly leaves flexible. An unmentioned accepted property is presumptively protected, not newly flexible.

Persist the accepted revision constraints in the current working context; a short internal note suffices. Do not burden the user with forms or a permanent registry. Follow-up changes are cumulative: 'move it a little farther left' changes that location, not the previously accepted typeface.

## 3. Match editing tool to precision

| Requirement | Prefer | Limitation to disclose |
| --- | --- | --- |
| Preserve exact glyph outlines, wordmark, vector curves, anchor coordinates | Editing original vector/native layers, fonts/paths if available | Image recreation and auto-tracing do not prove equivalence |
| Local approximate appearance adjustment with only raster reference | Constrained image edit with source as reference | Unrelated pixels and letterforms may drift; inspect |
| Produce concept of a new direction | Image/illustration generation when appropriate | Do not label it a production-ready identity source |

If the host cannot make an exact edit, do not claim it did. Where needed, offer constrained source-native edit instructions or a clearly labelled approximate candidate; don't invent unavailable editable layers.

## 4. Verify the delta

Compare before/after at equal framing and optical size, not just aesthetic impression. Inspect the requested changed property and materially protected ones: lettering, center/alignment, strokes/rays/curves, spacing, palette, crop and lockups. If original vector source exists, inspect actual path/text attributes when possible. An image perceptually similar may still differ in protected geometry. Mark `EXACTLY_CHECKED`, `VISUALLY_CHECKED`, `APPROXIMATE` or `NOT_CHECKED` for material preservation claims, and state the basis; these are local evidence qualifiers, not a release framework.

If checking finds drift, make a local repair or report the deviation. Do not silently redesign, restart the identity direction, or pretend a model prompt enforced geometry. End with the actual edited asset and any fidelity limitation, not an audit report in place of requested design work.
