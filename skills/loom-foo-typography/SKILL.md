# Typography — professional type judgment across media

## Critical contract

**Own typographic choices and results.** Determine type's communicative and functional role; use font and typesetting expertise to create, correct, or critique the requested design. Produce actual changed work where requested and feasible: a page, specimen, slide, component typography, responsive rules, or an editable design source. A list of nice fonts is not a finished type system; a screenshot is not editable source. Never claim that a font exists, supports a script, has a particular licence, or renders correctly without appropriate evidence.

**Preserve source:** authorized copy, language, terminology, user-provided typography/brand constraints, sizes and artifact destination. Do not silently edit spelling, wording or localization. If a text correction is needed, refer to `loom-foo-editorial-review` or ask for editorial authority; orthographic critique is not type critique.

**Judgment over recipes:** do not uncritically prescribe a universal modular scale, line-height value, character count, font pairing, all-caps rule, or geometric alignment. Requirements differ for UI, editorial, display, print, signage and other contexts. Evaluate optical quality at actual scale.

## Additional conditional detail

Use the regular typography procedure and existing conditional media/glyph references; read `references/PD_QUICK_CASES.md` only when a specific case analogy clarifies a nonstandard situation.

**Trigger:** A tricky type-script/media/optical-size scenario requires the detailed case analogies after the normal typographic method. Do not load this file for routine cases where that condition is absent.

## Activation and neighbors

Use when **typography is the central object or decision**: select or pair fonts, establish a type ramp, redesign a text-heavy page, repair Cyrillic glyphs, improve headings and copy layout, check typesetting, review optical alignment, develop localizable type styles, or troubleshoot text clipping and fallback.

- Standalone language proofreading, tone/style edits or punctuation -> `loom-foo-editorial-review` (Writing), when installed.
- **Focused typography verification, including read-only checks** (glyph coverage, line breaks, spacing, fallback, text reflow or overflow) stays with Typography. A request for *holistic critical judgment of an existing finished screen/poster* -> `loom-foo-design-review` when discoverable, even if typography is one relevant lens. The words “check” and “no edits” alone do not choose the owner.
- Broad visual concept/composition across media -> `loom-foo-design` or `loom-foo-graphic-design` when present.
- Architecture/governance and multi-consumer typography-token mapping -> `loom-foo-design-systems` **when discoverable**; Typography owns font craft, specimens and focused type checks, not global token/source authority.
- Creating/editing a specific Figma, document, slide or browser asset -> respect that tool's native procedure; this skill supplies the type decisions, not API mechanics.
- Typeface design or font-engineering (outlines, interpolation, kerning tables, compiled OTF/TTF) -> separate production specialty and tools; never imply a font was compiled by delivering a logo or SVG.

This skill works independently if other loom-foo skills are absent. Don't require the general Design skill to run first.

## Procedure: proportionate to task

1. **Establish the typographic brief.** Resolve source text, languages and scripts, reading context and distance, audience, medium, required format/editability, existing design-system tokens, typographic tone and constraints. Infer a sensible default when safe; only ask for a missing decision that blocks the requested output.
2. **Inspect current type evidence.** For an existing artifact, inspect the actual render plus source styles/fonts if accessible. Identify functional roles and visible problems without projecting conclusions from one screenshot onto an unobserved responsive state. For new work, inventory real copy lengths and hierarchy; long strings and mixed scripts may drive the design.
3. **Choose type strategy.** Establish role, voice, reading hierarchy, font family/style availability, body/display distinctions, proportion, measure, weight/optical size and layout rhythm. Try an alternate mechanism only when the decision is real. Load `references/TYPOGRAPHIC_SYSTEMS.md` for system-level work.
4. **Typeset or specify.** Apply optical spacing, line breaks, alignment, wrapping, punctuation visibility and actual glyphs to the real artifact. Preserve meaning. On multilingual, web-responsive or print work, load `references/SCRIPTS_AND_MEDIA.md` for relevant risks. When exact fonts aren't installed, explicitly mark substitution and do not claim a verified match.
5. **Check the actual artifact.** Inspect normal reading size plus relevant small/large/zoomed variants. Compare type roles, paragraph texture, overflow, orphaned headings, alignment and actual character rendering. Use `references/TYPE_VERIFICATION.md` for context-sensitive checks; a numeric contrast or CSS lint check is supporting evidence, not visual acceptance. Fix consequential defects and re-inspect.
6. **Deliver at requested fidelity.** Provide edited source/file or type specification, typography samples when useful, specific rationale and unresolved checks. Never present unrendered CSS as confirmed visual quality or a raster proof as editable typography.
