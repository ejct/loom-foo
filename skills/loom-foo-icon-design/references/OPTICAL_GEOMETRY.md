# Icon optics and symbol grammar

## Size before polish

A symbol has a recognition budget that shrinks with size. Find the silhouette and key counterforms first. Avoid excessive internal grilles, nostril-like voids, tiny gradients and outlines that turn into dots. Zoomed geometry can look perfectly symmetrical while perceptually off-center in use.

Use a vector grid for consistency but allow optical compensation: circles and diagonals can overshoot nominal edges; unequal color/negative space may require unequal geometry for balanced weight. Do not mechanically mirror highlights or shapes when the lighting direction or visual mass makes that wrong.

## Family grammar

Define target grid/size, stroke and fill strategy, corner vocabulary, cap/join, optical weight, alignment, number of recognizable semantic elements, active-state treatment, RTL mirroring exceptions and disabled/selected distinctions. Test the set at actual UI scale together with typography; avoid using color alone as meaning when relevant.

## App/product icon versus UI glyph

An app icon primarily identifies a product and may use color/material; a toolbar icon must communicate action consistently and often needs monochrome variants. A logo is part of a broader identity. Ensure each task's output contract is explicit before drawing.
