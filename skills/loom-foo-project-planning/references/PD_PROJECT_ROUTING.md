## 1. Route only when project planning is the real need

Use when the primary unresolved decision is how to proceed across a project or workstream: which route to prioritize, what to do after material new evidence or a blocker, how to stage a complex effort, or how to reach an outcome under changing resource/authority constraints. An initial project can be exploratory or partially decided; do not require a fully accepted proposal just to choose a useful provisional route. **Do not activate for ordinary continuation of an already authorized execution path.** When the user requests execution and route selection is a necessary intermediate step, plan briefly inside the execution episode and continue toward the outcome instead of returning only a plan.

Prefer a stronger specialist when the *primary output* is already clear:

- An actionable proposal for whether/what to build -> `loom-foo-proposal-refinement`.
- A new/changed system architecture -> `loom-foo-architecture-design`; evaluation only -> `loom-foo-architecture-review`.
- Semantic requirements/contract -> `loom-foo-specification-design`.
- A method for acquiring decision-relevant evidence -> `loom-foo-research-design`.
- An already accepted multi-unit scope to split into coherent Work Units -> `loom-foo-work-decomposition` directly.
- An already bounded, evidence-backed choice between alternatives -> `loom-foo-decision-reconciliation` if no stronger artifact owner applies.
- A reusable skill, skill portfolio boundary, or knowledge-delivery strategy -> `loom-foo-skill-engineering` (when available); not a general project route.
- The transfer of methods/lessons between projects -> `loom-foo-cross-context-transfer`; requested knowledge retrieval/intake -> `loom-foo-knowledge-retrieval`/`loom-foo-knowledge-intake` owners.
- One bounded task or prompt for an agent -> `loom-foo-agent-task-design`.
- An already authorized task that should now be *performed*, including normal fix/retry/verification -> the executor/owning workflow; do not replace action with planning.
- Reviewing a concrete change, verifying criteria, reviewing evidence or investigating a failure -> respective `loom-foo-change-review`, `loom-foo-change-verification`, `loom-foo-evidence-review` or `loom-foo-failure-learning` owners.
- Material ambiguity before any owner can work -> `loom-foo-problem-understanding` only as needed.
- A continuation checkpoint rather than a new route -> `loom-foo-handoff`.
- Cross-project portfolio priority/capacity, calendar scheduling, live dispatch and project-management status reporting -> their respective runtime/management owners, not this skill.

Do not wrap a sibling's work in a ceremonial planning phase. If project planning is useful only as a small part of another requested artifact, let that owner plan locally. Domain/platform skills retain their domain-specific methods when available. This package excludes Personal Finance and Chrome Extension Runtime as EXTERNAL, and archives ChatGPT Web Recon. If a needed specialist is absent, mark it **UNAVAILABLE**, do not make unsupported domain or live-site claims, and plan only the work still feasible under current evidence.
