# Understanding Model Contract

## Purpose

An Understanding Model is the smallest recoverable representation that makes a materially ambiguous situation intelligible enough for the user's current purpose or for a stronger downstream owner.

It is a semantic artifact class, not a mandatory document schema.

## Minimal quality conditions

A strong Understanding Model lets a competent receiver answer, when relevant:

1. What exactly are we trying to understand?
2. What is established versus interpreted, assumed, or unknown?
3. Which distinctions materially change the model?
4. Which alternative frames/explanations remain plausible?
5. What is the current best understanding?
6. What unresolved crux could change it?
7. Is understanding itself sufficient, or what owner should act next?

## Optional elements

Use only when material:

- subject/question;
- scope/exclusions;
- observations;
- accepted constraints/authority;
- interpretations;
- assumptions;
- alternative frames/explanations;
- causal/relational structure;
- tensions/contradictions;
- unknowns;
- controlling cruxes;
- current best model;
- change conditions;
- next owner.

## Persistence

Do not create a durable artifact merely because the skill ran.

Persist when:

- another agent/context must continue;
- the model will be reused by multiple downstream owners;
- provenance/versioning matters;
- the user explicitly requests durable documentation.

Otherwise an inline result is sufficient.

## Failure modes

- long summary without a model;
- list of assumptions with no controlling structure;
- false precision about unresolved facts;
- one-frame critique that never generates a plausible missing alternative;
- forced novelty after the initial model survives;
- artifact proliferation;
- recommendations that silently jump into proposal/decision authority.
