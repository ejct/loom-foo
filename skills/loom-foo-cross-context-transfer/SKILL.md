# Cross-Context Transfer

## Critical contract — read first

- **Goal fidelity:** Preserve the owner's real result, required actors, source identity, constraints and scope. Do not treat an intermediate result as completion unless it is the exact outcome the user requested and meets its acceptance criteria.
- **Authority and verification:** Tool access cannot grant new action authority. Keep evidence proportional to the actual claim and honor the scope, refusal, resource and acceptance boundaries detailed below.
- **Target identity and live constraints:** Before evaluating applicability to a named user project or the user's portfolio, resolve the target's current canonical name/aliases, owner decisions, constraints and controlling sources. For indexed targets, use `loom-foo-knowledge-retrieval` when relevant and available, or reuse a sufficiently current, sourced upstream receipt. Historical names, memory and source summaries alone do not establish current project state. Avoid unrelated knowledge-base reads for target-free DISTILL, generic comparisons or purely hypothetical examples. When access fails, bound the project-fit claim rather than inventing project state. Load conditional references when their trigger applies.

Transfer evidence-backed knowledge across contexts without cargo-cult copying.

The unit of transfer is the relation:

`problem + forces + mechanism -> consequence`

together with boundary conditions, failures, evidence status, and provenance.

## L1 — ordinary execution and L2 selection

Define target decision and bounded source corpus, preserve source identity and contradictory evidence, extract transfer units before fitting them to the target, and label observed versus inferred or unverified transfer. Complete source coverage cannot be claimed from snippets or a silently incomplete corpus.

Existing specialist references linked inside these materials remain conditional on their original situations. A moved section does not grant new permissions or replace the owning L1 safeguards.

A cross-language source alone or ordinary mechanism transfer with settled terminology is a non-trigger. ## 1. Determine intent

Use the narrowest mode:

- **DISTILL** — source -> transferable knowledge, no target.
- **TRANSFER** — source -> target.
- **COMPARE** — symmetric comparison.
- **SYNTHESIZE** — multiple contexts -> coherent combined model/direction.
- **GENERALIZE** — multiple cases -> reusable principle/pattern/method.

Do not force source->target framing when evidence implies synthesis, a shared substrate, or no useful transfer. Generalization from one case is a hypothesis unless independently supported.

## 2. Authority boundary

A transfer request authorizes analysis and production of candidate knowledge. It does not by itself accept source claims as target truth, change target authority, modify canonical docs/code/configuration, create a reusable Core primitive, copy external code, or implement anything.

Default to **knowledge transfer**, not artifact reuse.

## 3. Transfer Charter

Establish compact working state:

- user question / intent;
- source context(s);
- target context if any;
- expected output;
- source classes;
- scope / non-goals;
- accepted target decisions / constraints;
- known authority/evidence;
- material uncertainties;
- justified completeness claim if coverage closes;
- validation criteria.

## 5. Define corpus before synthesis

### Corpus Closure Invariant

Do not claim source completeness until every in-scope artifact has:

- stable source/version identity;
- coverage state;
- task-specific disposition;
- exclusion reason if excluded.

### No Silent Partial Evidence

Search snippets, retrieval chunks, summaries, metadata, truncated reads, capped folder listings, sampled code, or partial PDFs are not full review.

Coverage:

`FULL_REVIEWED | PARTIAL | METADATA_ONLY | FAILED | EXCLUDED`

Task disposition:

`MATERIAL | POSSIBLY_MATERIAL | NO_MATERIAL_RELEVANCE | SUPERSEDED | CONTRADICTORY | UNRESOLVED`

Read `references/CORPUS_COVERAGE.md` for consequential work.

For open-ended landscape or cross-domain discovery, treat the initial source set and search vocabulary as provisional. New materially relevant solution classes, terms, independent discovery channels, or references may expand the declared search scope. Record such expansions and exclusions proportionately; do not retroactively claim that a changing candidate universe was an exhaustive fixed corpus. For bounded source/transfer requests, preserve the specified scope instead of expanding it by default.

## Conditional frontier reconciliation

For material multi-source or continuation work, keep the existing corpus manifest and material-reference frontier recoverable with stable source identity, checked portions/method, remaining portions and disposition/next action. Reconcile new material reference candidates into the declared scope or record why they are excluded, deferred or blocked; a candidate is not a verified result or new action authority. When discoveries accumulate faster than checked material, prefer useful deep reads and neglected material branches before adding more leads; avoid repeated queries without a changed rationale. Continue authorized material work within the current episode until the declared coverage/closure gate, a real blocker, or a host boundary. Preserve exact remaining work rather than claiming convergence. For open discovery report known coverage and protocol limits, never a global percentage; deduplicate overlapping records and preserve scope changes. Do not impose this on trivial transfers.

## 7. Freeze mutable source identity

Capture relevant revision/modified time, commit/tag/branch/path, paper/spec version, publication date or retrieval date.

If a material source changes during the run, refresh affected conclusions or mark them stale.

## 11. Reconstruct source knowledge before target mapping

Extract source problems, forces, invariants, mechanisms, outcomes, causal/rationale claims, failures, boundary conditions, evidence status, and authority/currentness before searching for target matches.

Do not use source terminology as the target ontology.

## 12. Extract Transfer Units

A Transfer Unit is an ephemeral relational bundle, not a copied component.

Read `references/TRANSFER_UNITS.md` when mapping is non-trivial.

Every material final claim must remain traceable to original source evidence, even if intermediate summaries are used.

## 20. Terminal states

### `CONVERGED`
Coverage claims are justified; material frontier closed; no unresolved Critical/Major transfer finding; original provenance preserved; contradictions accounted for; target local-delta reasoning explicit; remaining uncertainty bounded; another pass has low expected information value.

### `VALIDATION_REQUIRED`
Target applicability requires empirical evidence.

### `BLOCKED`
Material source/target artifact, authority, version, or scope prerequisite is missing.

### `NON_CONVERGING`
Framing, corpus definition, or analogy remains unstable across revisions.

## 21. Output

Return decision-relevant transfer results, not a document-by-document dump.

Include when material:

- intent/source/target;
- coverage claim/gaps;
- important Transfer Units;
- contradictions/negative knowledge;
- target correspondences/mismatches;
- dispositions;
- candidate local deltas;
- validation;
- generalized lessons;
- provenance anchors;
- Transfer Closure.

For consequential work include a compact Coverage Closure.

## 23. Progress guard

Close the declared corpus, not the universe. Follow only material references. Expand target by affected concerns. Stop at empirical boundaries.

If exhaustive treatment is impractical, narrow scope explicitly rather than silently sampling.

Never weaken `No Silent Partial Evidence` to save time.
