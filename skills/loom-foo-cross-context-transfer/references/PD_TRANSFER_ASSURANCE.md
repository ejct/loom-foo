## 17. Adversarial Transfer Review

Freeze material transfer packages:

`T0 -> A0 -> T1 -> A1 -> ...`

Challenge:

- completeness claims;
- task-conditioned coverage;
- stale/superseded evidence;
- surface analogy;
- context mismatch;
- false causality;
- speculation as evidence;
- ignored negative knowledge;
- target confirmation bias;
- duplicated target owner;
- semantic collision;
- premature abstraction/merge;
- overlarge delta;
- ungrounded generalization;
- provenance loss;
- authority inversion.

Same-context review is a **fresh adversarial self-review**, not an independent review.
## 18. Adjudicate before revising

Treat findings as hypotheses. Reopen the smallest affected corpus item, Transfer Unit, mapping, or target concern. Preserve finding identity and regression-check material fixes.

Do not fix a weak analogy by inventing a larger abstraction.
## 19. Empirical boundary

When applicability depends on target behavior reasoning cannot establish, return:

- hypothesis;
- source-derived expectation;
- target-specific probe;
- measurement;
- discriminating boundary;
- which disposition changes under each result.

Use `VALIDATION_REQUIRED`.
## 22. Composition

- "What can X teach Y?" -> this skill owns. When Y is a named user project, consume or obtain current project authority before target-fit conclusions; no knowledge-index requirement for target-free DISTILL or generic technique explanations.
- "Design Y using X" -> `loom-foo-architecture-design` owns; this skill supplies transfer findings.
- "Prepare proposal to adopt X" -> `loom-foo-proposal-refinement` owns; this skill supplies candidate local deltas.
- "Review whether X fits architecture Y" -> this skill evaluates transfer validity; architecture review can separately evaluate Y.

Avoid recursive ownership.
