# Proposal Refinement

**Optional conceptual collaboration (L1).** When a consequential proposal remains trapped in one rejected mechanism family or its problem framing excludes credible alternatives, optionally consult `loom-foo-creative-reasoning` for a bounded reframe/divergence. Proposal Refinement keeps the final recommendation, evidence challenge and authority boundary. Ordinary proposal alternatives, reviews and settled decision execution do not require it. If `loom-foo-creative-reasoning` is unavailable, continue with normal subject-owner methods where possible; do not pretend that it was loaded or add an obligatory handoff.


**Owner / normal outcome.** Turn a project decision request into one useful, appropriately scrutinized proposal, without making an audit or comparative proof a precondition. Own proposals; NOT architecture-only design, a runnable agent task, or implementing accepted proposals.

## L1 — normal path

1. Establish the *actual owner-desired outcome*, what decision is requested, current state, accepted choices, sources, scope/non-goals, consequential unknowns and exact authorization. Do not require a visible charter as ritual.
2. Check **local delta** against existing owners/decisions. If the requested behavior is already covered, return an evidenced `NO_LOCAL_DELTA` disposition, not an invented new mechanism.
3. Build the *proposal before auditing it*: smallest credible baseline, real alternatives where a choice exists, recommended delta, why now, drivers/trade-offs, reversibility, concrete next decision, and a check that could falsify a load-bearing premise. A quick request should receive a quick proposal; do not manufacture weak alternatives.
4. For consequential proposals, check completeness and fresh-reader intelligibility, then challenge genuinely load-bearing assumptions, scope/authority leakage, missed simpler solutions and affected scenarios. Repair supported material findings and recheck their consequences. One challenge often suffices; repeat only after a material fix, new evidence or still-open defect, not to meet a round quota.
5. End in `CONVERGED`, `VALIDATION_REQUIRED`, `BLOCKED` or `NON_CONVERGING` only as justified by actual evidence. `VALIDATION_REQUIRED` is not an automatic development stop for reversible authorized work. Return the coherent latest proposal, not an audit transcript.

**Hard rules:** evidence gap ≠ permission to substitute benchmarking for functional progress; a proposal does not authorize acceptance/persistence/implementation; same-context review is not independent; never invent review findings, versioned artifacts or work done. Include material corrected defects and evidence boundaries only when needed.

## Conditional method index

- **Any project proposal whose goal/source/authority is uncertain or that affects project-native files:** read `references/PD_PROPOSAL_SCOPE.md` (original charter, source/provenance and authority details).
- **Consequential proposal, materially open solution space, external precedent, new reusable concept or meaningful option trade-off:** read `references/PD_PROPOSAL_CONSTRUCTION.md` plus the existing `references/PROPOSAL_QUALITY_CONTRACT.md`; do not force prior-art search for a routine bounded decision.
- **Material complexity or a proposed separate review of a durable consequential candidate:** read `references/PD_PROPOSAL_QUALITY.md` for construction/fresh-reader checks.
- **Actual substantial challenge, unresolved MAJOR/CRITICAL finding, repair or consequential review:** read `references/PD_PROPOSAL_REFINEMENT.md`; for a checkable critical claim read `references/CONSEQUENTIAL_CLAIM_CHALLENGE.md`.
- **Material proposal closure, repeated revision or disputed terminal state:** read `references/PD_PROPOSAL_CLOSURE.md`.

**Non-triggers:** normal quick bounded proposals need no mandatory deep reference stack, fixed audit rounds, explicit holdout, independent reviewer or artificial approval step. Keep all read claims and Process Trail evidence-scoped.
