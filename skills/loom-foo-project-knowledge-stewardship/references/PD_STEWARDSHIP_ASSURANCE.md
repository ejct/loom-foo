## 17. Candidate validation requirements

Before retention/promotion, test at least:
- accepted artifact already authoritative -> `NO_DURABLE_DELTA`;
- accepted new version supersedes old + index update;
- converged proposal but not accepted -> `NEED_AUTHORITY`;
- verification PASS but no owner acceptance -> `NEED_AUTHORITY`;
- stale PROJECT_STATE only;
- stale index + overview;
- historical old wording intentionally untouched;
- genuine authority conflict;
- two apparent current sources;
- inaccessible derived surface -> partial reconciliation;
- runtime projection requiring separate approval;
- project with no central index/registry;
- project-native ADR convention;
- bootstrap/handoff/context negative routing;
- comparison against ordinary project-native documentation updates;
- fresh holdout after candidate freeze.

Behavioral validation may remain deferred by portfolio policy. Static/package construction is not promotion evidence.
## Final checks

Before returning:
- authority transition is explicit;
- no self-canonization occurred;
- native project owners were reused;
- authoritative/derived/historical/projection surfaces are not conflated;
- minimum consistency set stayed bounded;
- historical provenance was preserved;
- no unnecessary durable artifact/schema was created;
- current state is no more ambiguous after the run;
- Project Knowledge Delta is compact and points to actual durable sources;
- no acceptance, publication, external action, or runtime/account mutation is claimed unless separately authorized and actually performed.
