# Consistency Surface

The consistency surface is the smallest set of durable project-native representations that must change after an authorized transition to avoid material future error.

## Candidate surface classes

- authoritative source;
- current source map / documentation index;
- project overview / status surface;
- decision/active-state registry;
- PROJECT_STATE or project-native continuity equivalent;
- runtime routing/instruction projection, under separate authority;
- supersession/backlink metadata where project convention uses it.

## Include a surface when staleness can plausibly cause

- wrong current/authority selection;
- invalid continuation;
- duplicate/conflicting implementation;
- broken discovery/navigation;
- materially false project status;
- wrong routing/policy/profile selection.

## Exclude by default

- historical narrative that was accurate at the time;
- old audits/evidence packages;
- every textual mention of the superseded state;
- generated copies with no downstream consumer;
- unrelated documentation.

## Verification

After mutation, verify only material identity/link/status properties. Do not turn stewardship into a full change-verification campaign unless a separate verification owner/contract requires it.
