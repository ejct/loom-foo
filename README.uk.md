# loom-foo

**Мова:** [English](README.md) · Українська

**Спеціалізовані Agent Skills для дизайну, досліджень, розробки продуктів, роботи з текстами та AI-агентами.**

Досліджуйте продуктову ідею. Удосконалюйте інтерфейс. Перевіряйте докази. Плануйте зміни. Ставте чіткі завдання агентам розробки. Перевіряйте, що саме вони виконали.

**loom-foo** — це набір із **40 портативних Agent Skills**. Кожна навичка визначає, коли її доречно використовувати, як працювати із завданням, який результат отримати та яких обмежень дотримуватися. Можна застосувати одну навичку або поєднати кілька, якщо вони доповнюють одна одну.

## Почніть із реального завдання

Якщо loom-foo встановлено у вашому AI-клієнті, просто опишіть свою задачу:

> Допоможи перетворити сиру продуктову ідею на чітко визначену проблему, корисну концепцію та практичні наступні кроки.

Інші приклади:

> Проаналізуй цей онбординг. Визнач найважливіші проблеми зручності використання та запропонуй конкретні покращення.

> Досліди це продуктове рішення. Порівняй реалістичні альтернативи, відокрем докази від припущень і поясни, що могло б змінити висновок.

> Перетвори ці вимоги на чітко обмежене завдання для AI-агента розробки: визнач обсяг робіт, обмеження та критерії приймання.

> Перевір цю реалізацію на дефекти, а потім звір її з погодженими критеріями. Відокрем результати рев'ю від результатів перевірки відповідності.

Не потрібно запам'ятовувати назви навичок. AI-клієнт із підтримкою автоматичного виявлення навичок **може** обрати потрібну за змістом запиту. Якщо такої можливості немає, виберіть навичку в [каталозі](skills/) і попросіть агента прочитати її `SKILL.md`.

## Як працюють навички

loom-foo використовує [формат Agent Skills](https://agentskills.io/). Точка входу кожної навички — файл `skills/<skill-id>/SKILL.md`. За потреби до неї додають довідкові матеріали, приклади, скрипти або ресурси.

Основні принципи роботи:

- **Відштовхуватися від завдання.** Обирати спеціалізований підхід під потрібний результат замість універсального процесу для всіх випадків.
- **Завантажувати контекст вибірково.** Читати додаткові матеріали тоді, коли вони справді потрібні.
- **Спиратися на докази.** Розрізняти спостереження, припущення, пропозиції та перевірені результати.
- **Дотримуватися меж повноважень.** Інструкції не дають доступу до приватних даних і не дозволяють самостійно публікувати, розгортати, витрачати кошти чи приймати зміни.
- **Не ускладнювати процес без потреби.** Застосовувати стільки методики, скільки потрібно для корисного й надійного результату.

Навички можуть доповнювати одна одну. Проте зв'язки між ними — це можливі способи роботи, а не гарантія того, що AI-клієнт автоматично їх активує.

## Як почати

Можна переглянути вихідний код на GitHub або клонувати репозиторій:

```sh
git clone https://github.com/ejct/loom-foo.git
```

Далі скористайтеся способом, який підтримує ваш AI-клієнт:

1. **Вбудоване встановлення навичок або плагінів.** Дотримуйтеся інструкцій і налаштувань доступу свого клієнта. Репозиторій містить маніфести для OpenAI/ChatGPT і Codex, Claude, Google Antigravity та Gemini. Способи встановлення й виявлення навичок відрізняються між середовищами.
2. **Пряме використання навички.** Надайте агенту доступ до потрібної директорії `skills/<skill-id>/` і попросіть прочитати `SKILL.md`.

Наприклад:

> Прочитай `skills/loom-foo-design-review/SKILL.md` і застосуй цю навичку до інтерфейсу, який я надам. Завантажуй додаткові матеріали лише за потреби. Відокрем спостережувані проблеми від гіпотез.

Клонування репозиторію або наявність маніфесту ще не доводить, що навички автоматично виявляються, правильно обираються чи однаково працюють у різних AI-клієнтах.

### Вимоги та вартість

Потрібен AI-клієнт, здатний читати й виконувати інструкції навичок, а також інструменти й доступ до джерел, необхідні для конкретного завдання. **Сам пакет навичок не потребує бекенду від розробника, платного API чи централізованого оркестратора.** AI-клієнт і підключені інструменти можуть мати власні тарифи, обмеження та правила обробки даних.

## Структура репозиторію

- [`skills/`](skills/) — навички та допоміжні матеріали
- [`SKILL_INVENTORY.json`](SKILL_INVENTORY.json) — точні ідентифікатори й версії навичок
- [`plugin.json`](plugin.json) та маніфести інших середовищ — метадані пакета
- [`CHANGELOG.md`](CHANGELOG.md) — історія змін вихідного коду
- [`CONTRIBUTING.md`](CONTRIBUTING.md) — пропозиція та перевірка змін
- [`SUPPORT.md`](SUPPORT.md), [`SECURITY.md`](SECURITY.md), [`PRIVACY.md`](PRIVACY.md), [`TERMS.md`](TERMS.md) — підтримка та правила проєкту

Кожна навичка має власну версію, незалежну від версії всього пакета.

## Стан і обмеження

**Публічна попередня версія вихідного коду.** Репозиторій доступний усім, але окремий публічний реліз із Git-тегом або випуск у каталозі плагінів ще не опубліковано. Підготовку релізу, перевірку конфіденційності Git-історії та сумісність із середовищами описано в [Release Status](RELEASE_STATUS.md). Отримати вихідний код — не те саме, що встановити перевірений плагін. Поточний кандидат **ще не схвалено для публікації** як окремий реліз із тегом або як пакет у каталозі; відкритий доступ до коду сам собою не є схваленням релізу.

Навички задають методи роботи для AI-агентів, але не гарантують правильності результатів. Вибір навички, застосування інструментів і перевірка залежать від AI-клієнта та його повноважень. Успішні статичні тести не доводять, що клієнт справді обрав і виконав навичку.

Із запитаннями та повідомленнями про помилки без конфіденційних даних звертайтеся через [GitHub Issues](https://github.com/ejct/loom-foo/issues). Не публікуйте паролі, секрети чи приватні матеріали проєктів.
